# Спека: A/B-сравнение фреймтайма «лимитер OFF vs ON» (slug: ab-compare)

## Цель
Видеть разницу ровности до и после включения ограничения FPS: p50/p99 фреймтайма и FPS отдельно для периодов с выключенным и включённым лимитером.

**Важно**: это сравнение ФРЕЙМТАЙМА (ровность), не задержки. Добавленная задержка по архитектуре = 0; измерение present→экран — отдельная задача (не в этом скоупе).

## Подход (рекомендованный, выбран пользователем)
Только app-сторона, ноль изменений в хуке/протоколе. Источник состояния лимитера — уже существующий `SharedState.limiter_on` (ставится в `push_config`, обновляется при toggle через трей/хоткей/UI).

## Изменения

### 1. `crates/iframe-app/src/live.rs`
- Новый struct `SideStats { samples: VecDeque<(f64 /*t,s*/, f64 /*ft_us*/)>, fps: f64, p50_us: f64, p99_us: f64, total: u64 }` (Default).
- `LiveStats` получает поля `on: SideStats`, `off: SideStats`. Существующие поля не трогаем (график не меняется).
- Воркер: локальные деки `on_samples`/`off_samples`; каждый кадр попадает в бакет по `state.limiter_on` на момент дренирования батча (гранулярность 20 мс — погрешность атрибуции ≤ 20 мс на переключателе, приемлемо).
- Каждое ведро тримится по времени до `HISTORY_SECONDS` (10 с) от своего нового сэмпла — OFF-ведро «замораживается» на последних 10 с периода OFF после переключения.
- Статистика ведра: FPS = 1e6/mean(ft), p50/p99 по всему окну ведра (не 1 с — устойчивее для сравнения).
- Чистая функция `fn side_stats(samples) -> (fps, p50, p99)` + unit-тест (известные сэмплы → ожидаемые p50/p99/fps).

### 2. `crates/iframe-app/src/ui.rs`
- Под существующим рядом статистики — компактный блок `egui::Grid` (3 колонки):
  ```
                 limiter OFF (before)   limiter ON (after)
  FPS            238.4                  40.1
  p50            4.20 ms                25.01 ms
  p99            4.35 ms                25.42 ms
  ```
- Пустая сторона (кадров < 2) → «—». Заголовок: «frametime, last 10 s per state».
- ETW-режим: лимитер неприменим → будет заполнена только OFF-сторона (корректно).

## Не меняется
- `iframe-common`, `iframe-hook`, протокол shared memory, CLI, ETW.
- Существующие общий график и ряд статистики (FPS/p50/p99/late/frames) остаются как были.

## Допущения (не спрашиваю — отмечаю)
- Окно каждого состояния = 10 с (как у графика, `HISTORY_SECONDS`).
- Ведра живут в воркере → при re-attach сбрасываются (как и текущая статистика).
- Переключение лимитера в середине 20-мс батча может отнести ≤20 мс кадров не в ту сторону — несущественно.

## Проверка
1. `cargo test -p iframe-app` — новый юнит-тест статистики.
2. `cargo check --workspace` — без новых ошибок.
3. Вручную: стенд `d3d11_test_app` → inject → лимитер 40 FPS → toggle Ctrl+Alt+I → в UI заполняются обе колонки, значения меняются соответственно.
