## 1. ЧТО ИСПРАВИТЬ (баги) — P0

### 1.1. 🔴 Нет watchdog'а хоста: лимитер живёт вечно после смерти UI
**Самая серьёзная находка.** `SharedHeader` (shared_mem.rs:59-83) не содержит heartbeat-поля.
Конфиг пишется в shared memory один раз; DLL читает его каждый кадр (engine.rs:63-66).
Если процесс iFrame убит (Task Manager, краш, kill) — `Drop` не выполняется, и **лимитер
остаётся включённым в игре с устаревшими настройками навсегда**, пока игра не закроется.
Грейсфул-выход обрабатан (ui.rs:782-800), но краш/kill — нет.

**Фикс:** поле `host_heartbeat_qpc: AtomicU64` в хедере; UI-воркер (live.rs, уже тикает каждые 20 мс)
обновляет его; DLL в `pace()` при устаревании >3 с принудительно отключает пейсинг.
Нюанс дизайна: CLI `iframe limit` пишёт конфиг и выходит — надо различать «хоста никогда не было»
(CLI-режим, конфиг persists) и «хост умер» (отключить). Решение: флаг `host_present`,
который ставит только живой хост; `limit --hold` — опциональный демон-режим для CLI.

### 1.2. 🔴 `pid_from_window_title("")` находит чужое окно (красный тест)
`FindWindowW(NULL, "")` матчится по классу — тест `l2_boundary_window_title_empty_and_special` падает.
Фикс: reject пустых/blank заголовков до `FindWindowW` (injector.rs, ~1 строка).

### 1.3. 🔴 DWM врёт о герцовке, а в UI нет ручки override
Живой факт: `DwmGetCompositionTimingInfo` вернул 240 Гц при мониторе 120 Гц → лимитер 40 FPS дал 112–136 FPS.
CLI имеет `--refresh`, UI — нет: `push_config` (ui.rs:244) жёстко шлёт `refresh_hz: 0.0`,
в `GameProfile` (profiles.rs) поля refresh тоже нет.
**Фикс:** поле «Частота монитора (override)» в UI + `refresh_hz` в профиль + автоподстановка
из `EnumDisplaySettingsEx` для монитора, на котором окно игры (`MonitorFromWindow`).

### 1.4. 🟡 Логика вердиктов bench врёт
Живой вывод: `✔ [Jitter Reduction]: 0.1x improvement (±0.84 ms → ±15.76 ms)` — джиттер
ухудшился в 18 раз, но стоит ✔. «NEGATIVE LATENCY: 30.8 ms SAVED» — теоретическая модель
(3 × frametime), поданная как измерение. **Фикс:** честное сравнение (✔/✖), пометка
«оценка модели» у pipeline lag, иначе инструмент дискредитирует сам себя.

### 1.5. 🟡 Ошибки attach невидимы в GUI
`log_ui` = `eprintln!` (ui.rs:909-911). Запущенный из Explorer GUI не имеет консоли —
пользователь не видит НИ одну ошибку («inject failed», «ETW failed 0x80070005» и т.д.).
**Фикс:** кольцевой буфер событий + панель «Журнал» в UI (там же — подсказка «запустите от админа» для ETW).

### 1.6. 🟡 watch/bench: мусор в max/p99 от пауз
Живой факт: `max: 14801494.80 µs` (14.8 с!) в первом сегменте watch — это разрыв между
attach и первым Present'ом. **Фикс:** фильтровать паузы > 1 с в отдельную категорию «stall»,
не смешивать с фреймтаймом; в live.rs первый сэмпл уже корректно пропускается — привести watch к тому же.

### 1.7. 🟢 Мелочи
- `--version` не обрабатывается (падает в unknown command); в usage нет `watch-etw`. (`--help` работает — здесь я в прошлом отчёте ошибся.)
- Лог хука: один `iframe_hook.log` на все процессы → interleaved-мусор (наблюдалось); кириллица µs бьётся при чтении в OEM-консоли. Фикс: `iframe_hook_<pid>.log` + UTF-8 BOM.
- Clippy: только 16 style-предупреждений (collapsible_if) — код чистый, реальных багов линтер не нашёл.

## 2. ЧТО ДОРАБОТАТЬ (надёжность/корректность) — P1

### 2.1. VSync override работает ТОЛЬКО для DXGI
Греп по всему коду: нет `wglSwapIntervalEXT` (OpenGL), нет `PresentEx`/`PresentationInterval` (D3D9),
нет управления present mode (Vulkan). Чекбокс «override VSync» в UI для D3D9/GL/Vulkan-игр
**молча ничего не делает** (пейсинг при этом работает — он API-агностичен).
- D3D9: добавить хук `PresentEx` (слот рядом с Present@17) — override интервала.
- OpenGL: `wglSwapIntervalEXT(0)` при инициализации хука — просто.
- Vulkan: честно задокументировать «pacing only».
- UI: дизейблить чекбокс для не-DXGI целей.

### 2.2. Нет `SetMaximumFrameLatency`
Для УЖЕ созданных swap chain (инъекция после запуска игры) waitable-флаг добавить нельзя,
но `IDXGISwapChain2::SetMaximumFrameLatency(1)` — можно. Сейчас не вызывается нигде.
Это уменьшило бы очередь DXGI до 1 кадра в большинстве сценариев и сделало бы заявление
bench про «Queue Depth ~1 (override)» фактически истинным.

### 2.3. Пейсер один на процесс, а не на swap chain
`ENGINE: Mutex<Option<Engine>>` (engine.rs:21) — синглтон. Игра с двумя swap chain
(PiP-видео, оверлеи, некоторые лаунчеры) даст перемежающиеся Present'ы в один оценщик →
испорченная EMA. `try_lock` спасает от параллельных Present'ов, но не от чередования.
**Фикс:** карта `swapchain_ptr → JitPacer` (прокинуть идентификатор через hooks → engine).

### 2.4. Torn-чтение конфига
`set_config` пишет 6 атомиков по отдельности (shared_mem.rs:242-258) — DLL может увидеть
смесь старого и нового конфига (например, новый fps + старый enabled). Один кадр глюка.
**Фикс:** sequence counter (запись: seq++ нечётный → поля → seq++ чётный; чтение: retry).

### 2.5. Безопасность shared memory
Имя `Local\iFrameSM_<pid>` угадываемо, маппинг с DACL по умолчанию и `FILE_MAP_ALL_ACCESS`
(sm_host.rs:53-63) — любой процесс того же пользователя может переписать конфиг игры.
Севёрность низкая (локально), но дёшево закрыть: случайный суффикс имени (передавать DLL
через параметр) + DACL только для текущего пользователя.

### 2.6. Инъекция UX
- Нет определения elevation: инъекция в игру от админа из не-админ UI падает с криптикой. Детект + понятное сообщение + (опционально) self-elevation.
- CreateRemoteThread + LoadLibraryW — классический триггер для AV/SmartScreen (ложные срабатывания на СВОЁ приложение). Это не про обход античитов (отказ в защищённые процессы уже есть и должен остаться), а про подпись кода / документацию исключений Defender.
- Нет `iframe uninject`: DLL живёт до выхода игры. Добавить экспорт `iframe_eject()` (FreeLibraryAndExitThread) + CLI-команду (аккуратно: выгрузка из чужого потока — только через удалённый поток).

### 2.7. Мульти-монитор
Vblank-фаза берётся с первичного монитора; игра на втором мониторе с другой герцовкой получит
неверную сетку. Фикс: определять монитор окна игры, cross-check с DWM-хинтом, при расхождении —
доверять EnumDisplaySettings + предупреждать в журнале UI.

## 3. ЧТО РАСШИРИТЬ (фичи) — P2/P3

### Флагманские (сильнее всего меняют продукт)
1. **In-game оверлей** (как RTSS): кликабельный-насквозь always-on-top egui viewport с FPS/фреймтаймом поверх игры. У iFrame уже есть вся телеметрия — оверлей это дёшево и очень заметно.
2. **Экспорт сессий**: CSV/JSON (кнопка в UI + `watch --json`) — метрики p50/p99/jitter/late за сессию. Основа для сравнений «до/после» и репортов.
3. **Мульти-таргет**: SM уже per-pid, CLI уже умеет несколько игр — UI привязан к одной. Табы/список подключений.
4. **Авто-тюнинг**: кнопка «подобрать настройки» — у вас уже есть `optimize-config` (CDCL-солвер), но он не интегрирован в рантайм. Связать: solver → профиль игры.

### Полезные
5. Трей: иконка-состояние (зелёный = лимитер ON, серый = OFF), FPS в tooltip.
6. Настраиваемый хоткей (сейчас жёстко Ctrl+Alt+I) в profiles.toml.
7. Фильтр списка окон: сейчас там браузеры и IDE. Эвристика «похож на игру»: в процессе загружен d3d11/dxgi/vulkan/opengl32 модуль, или окно fullscreen.
8. `iframe status --pid N` — читает состояние ring (config, hook_state, dropped) для скриптов; `--json` для watch/list.
9. `iframe doctor` — самодиагностика: админ-права, DWM, тест-инъекция в test app, права на SM, версии DLL. Сильно снизит поддержку.
10. `bench --exe <path>` — бенчмарк произвольного приложения, а не только встроенного тест-стенда.
11. Тест-стенды для D3D9/OpenGL/Vulkan (сейчас только D3D11) — закрыть E2E-пробел по 2.1.
12. Warmup-исключение: первые ~0.5 с после attach не учитывать в A/B-статистике (сейчас портит p99/max).

### Далёкая перспектива
13. Scanline-sync режим (пейсинг на конкретную строку развёртки, как RTSS) — для VRR-мониторов.
14. i18n: UI сейчас только русский; английский для дистрибуции.
15. Импорт/экспорт профилей, редактор профилей в UI.

## 6. Чего делать НЕ надо
- Обход античитов / stealth-инъекция — противоречит архитектуре (честный отказ в защищённые процессы + ETW telemetry-only). Оставить как есть.
- Переписывать SPSC-кольцо или пейсер — они покрыты 63 тестами и ведут себя корректно в живых прогонах; риск регрессий выше пользы.
- Внутрипроцессный перехват vkCreateSwapchainKHR для смены present mode — хрупко и опасно; достаточно pacing'а.
