### ETW telemetry-only — наблюдение без инъекции ✅

- Real-time сессия на **Microsoft-Windows-DxgKrnl** (тот же источник, что PresentMon) через ferrisetw 1.2.0
- Present-события (ID 42/126 + flip-варианты), фильтр по ProcessId-свойству события
- Frametime из дельт timestamp'ов → **тот же live-график**, что в режиме инъекции
- **Ноль инъекции** — нечего детектить античиту

**Честное ограничение:** ETW kernel-tracing требует прав администратора (0x80070005 подтверждён живым тестом) — то же требование, что у PresentMon. Сообщение об ошибке подсказывает «запустите от администратора». Ручная проверка: `iframe.exe watch-etw --pid N` из elevated-консоли.

### Автоматический fallback в UI

`attach()` на защищённой цели: отказ инъекции → **автоматический переход** в ETW-режим (статус attached, exe_name, лог «telemetry-only ETW mode active»). `detach()` корректно останавливает сессию. CLI: новая команда `watch-etw --pid N`.

### 🤖 Argent
Нет, в v1.0.0 не поддерживаются. Текущее покрытие:

| API | Статус | Как хукается |
|---|---|---|
| **D3D11** | ✅ полная поддержка | vtable-патч IDXGISwapChain (Present@8, Present1@21) + хуки фабрики |
| **D3D12** | ✅ полная поддержка | D3D12 презентуется через тот же DXGI-свопчейн — покрывается теми же хуками |
| **D3D9** | ⚠️ частично | IAT → CreateDevice → Present@17; d3d9.dll строит vtable динамически и откатывает патчи (анти-тампер) |
| **Vulkan** | ❌ нет | — |
| **OpenGL** | ❌ нет | — |

**Почему не поддерживаются:** весь наш механизм построен на COM vtable-патчинге — у Vulkan и OpenGL его нет:

- **OpenGL** — презентация через `wglSwapBuffers`/`wglSwapLayerBuffers` из opengl32.dll. Хук = IAT-патч, **та же механика, что уже сделана для D3D9** (Direct3DCreate9). Умеренная сложность, переиспользует существующий код. Пейсер (JitPacer) API-агностичен — нужен только новый хук-пойнт.

- **Vulkan** — сложнее: функции выдаются через `vkGetDeviceProcAddr`, диспетч-таблицы, не vtables. Чистый официальный путь — **Vulkan layer** (как у OBS): загрузчик сам подгружает наш слой, перехватываем `vkQueuePresentKHR` — и даже инъекция DLL не нужна. Но слои могут флагаться античитами (тот же Vanguard), и это отдельный механизм доставки кода. Альтернатива — хук диспетчеризации, грязнее.

**Итого:** OpenGL — реалистичное расширение на существующей базе; Vulkan — отдельный этап с новым механизмом (layer). Если нужен какой-то из них — скажи, начну с оценки и плана.
